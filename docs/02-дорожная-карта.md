# Дорожная карта

Принцип: **каждый этап заканчивается работающей вещью**, а не «инфраструктурой».
Первая реальная польза — на этапе 2 (уход с подписки), не в конце.

---

## Э0. Каркас и спецификация — 1–2 вечера, железо не нужно

- Имя, лицензия, репозиторий (см. открытые решения в `03-риски-и-решения.md`).
- Spec Kit: `specs/spec.md` → план → `specs/tasks.md` (задача крупная и многофайловая —
  порог SDD пройден). Отдельный `plan.md` так и не заведён: план жил в ТЗ пакетов.
  Спецификация и ТЗ — рабочие документы автора, в публичную копию не входят.
- Эталонный набор для метрик: 30 минут реальной русской речи с нагрудного микрофона
  + транскрипт вручную → `tests/wer/`. Без него «стало лучше» недоказуемо.

**Готово, когда:** есть спека с трассируемыми требованиями и эталон для WER.

## Э1. Ядро на файлах — 2–4 вечера, железо не нужно

Собирается и проверяется на WAV-файлах, кулон не требуется.

1. `POST /ingest` — приёмник, **совместимый с форматом Omi**
   (`?sample_rate=16000&uid=…`, raw PCM, `application/octet-stream`).
   Это даёт бесплатный тестовый стенд: официальное приложение Omi умеет слать
   сырой звук на любой URL (Settings → Developer Mode → Realtime audio bytes).
2. Silero VAD → нарезка на реплики → склейка в разговоры по паузам и смене говорящих.
3. STT-роутер: Groq `whisper-large-v3` (быстро) + локальный `faster-whisper` (бесплатно).
   GigaAM — следующим шагом, после первого замера WER.
4. NLU через большую модель: саммари, факты, задачи (с P5 — Ollama на этом ПК).
5. Хранилище SQLite + запись в Obsidian.

**Готово, когда:** 30-минутный файл на входе → транскрипт, саммари и задачи на выходе,
WER посчитан и записан в `tests/wer/` (на 24.09 не сделано — нет эталона, гейт A1).

## Э2. Мост на ПК — 1–2 вечера ⬅️ **первая реальная польза**

Демон на `bleak`: подключается к уже собранному кулону со **штатной прошивкой Omi**,
декодирует Opus, шлёт в ядро. Всё уже проверено вживую 21.08.2026 (адрес вида `AA:BB:CC:DD:EE:FF`),
кодек 20 (Opus 16 кГц), поток 4,6 КБ/с, Bluetooth на ПК есть.

С этого момента подписка Omi не нужна: запись, расшифровка, память и Telegram — свои.

**Готово, когда:** сутки носки → утром в Telegram сводка, в Obsidian лог, подписка не тратится.

⚠️ Пока ПК держит BLE-соединение, телефон кулон не видит — это нормальная работа BLE,
а не поломка.

---

## Э3. Своя прошивка — 1–2 недели, главный технический этап

Форк firmware Omi (Zephyr, MIT). По одному изменению за раз, с замером после каждого:

| Шаг | Что даёт |
|---|---|
| Opus DTX + битрейт 16–24 кбит/с | трафик в тишине → почти ноль |
| Gate до энкодера (энергия + ZCR, pre-roll 300 мс, hangover 800 мс) | CPU спит в тишине |
| LE 2M PHY + осмысленный connection interval | меньше времени радио включено |
| Wear-detect по IMU (неподвижен > 2 мин → сон) | кулон на столе не жрёт батарею |
| Тапы по IMU: 2 — метка, 3 — приват на 10 мин | управление без кнопки и без телефона |
| Кольцевой буфер в QSPI 2 МБ + докачка | аудио не теряется при уходе телефона |
| LED-индикация записи | правовой щит и признак «честного» устройства |
| MCUboot: две банки, откат при неудачном старте | OTA перестаёт быть рулеткой |

⚠️ Обязателен инструмент замера тока (USB-амперметр или INA219). Без него все
заявления по автономности — слова.

🛑 Правило по железу, выученное 21.08.2026: **прошивку из приложения Omi не обновлять**;
накатывать только по USB через двойной RST; при OTA кабель должен быть отключён.

**Готово, когда:** замеренная автономность ≥ ×2 к штатной прошивке на той же банке 250 mAh,
средний трафик ≤ 1,5 КБ/с, кулон переживает 15 минут без телефона без потери аудио.

## Э4. Android-мост — 1–2 недели

RN/Expo + `react-native-ble-plx` (есть готовый `@omiai/omi-react-native`), foreground
service, переподключение, дисковая очередь, выгрузка пачками по Wi-Fi / VPN
(не realtime — экономит батарею телефона).

Отдельно проверить: Doze, вендорский убийца фоновых сервисов, разрешения BLE Android 12+.

**Готово, когда:** сутки с телефоном в кармане без ручного вмешательства, ноль потерь.

---

## Э5. Продуктизация — 1–2 недели

- `docker compose up -d` → ядро + Qdrant + веб-UI одной командой; `.exe` для Windows.
- MCP-сервер (stdio + SSE) со сжатым набором инструментов: разговоры, поиск, люди,
  задачи, метки.
- Вебхуки с HMAC + SDK Python/TS.
- Коннекторы: Telegram, Obsidian, n8n.
- Локальный веб-UI: лента дня, поиск, люди, задачи, панель приватности.
- Документация «от нуля до первого события за 10 минут».

**Готово, когда:** на чистой машине посторонний человек по инструкции доходит
от установки до события в своём скрипте за ≤ 10 минут.

---

## Э6. Своё железо — опция, только если продукт подтвердился

Своя плата: nRF52840 (или nRF54L15) + зарядник с током > 100 мА (упор XIAO —
BQ25101 с 50 мА, банку больше 250 mAh на нём просто не зарядить) + QSPI 16 МБ
(> 2 часов речи в буфере) + физическая кнопка + RGB-LED + банка 400–600 мА·ч + корпус.

До этого этапа своё железо не нужно: работаем на кулонах Omi/Friend, включая чужие.
