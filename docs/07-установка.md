# Установка с нуля

*English → [en/07-install.md](en/07-install.md)*

Инструкция проверена 20.09.2026 автоматической приёмкой (служебный скрипт автора):
пустая папка → клон → окружение → все тесты зелёные → живое ядро → приём звука →
реплика в базе → MCP отвечает. Всё на Windows 11, Python 3.12.10.

Дальше — по нарастающей. **Шаги 1–5 дают рабочее ядро** и их достаточно, чтобы
проверить установку. Шаги 6–10 включают то, ради чего всё затевалось:
расшифровку на видеокарте, локальный разбор, кулон, телефон, окно на ПК.

---

## 0. Что нужно иметь

| | Нужно | Зачем | Без этого |
|---|---|---|---|
| обязательно | Python **3.12** | всё ядро | никак |
| обязательно | git | клон | можно скачать архивом |
| обязательно | ~1 ГБ на диске | окружение и зависимости | никак |
| для скорости | видеокарта NVIDIA + драйвер | расшифровка на GPU | считает процессор, в разы дольше |
| для разбора | [Ollama](https://ollama.com) | факты и задачи из разговора | реплики есть, выводов нет |
| для кулона | Bluetooth LE на ПК | мост `bridge/` | звук только из приложения Omi |
| для заметок | Obsidian | выгрузка дней | заметки лягут файлами, читать можно чем угодно |

Место: окружение ~450 МБ, CUDA-колёса +2,0 ГБ, whisper `large-v3` ~3 ГБ,
модель разбора 4,7 ГБ, модель поиска 255 МБ. **Полный комплект — около 10,5 ГБ.**

## 1. Клон

```powershell
git clone https://github.com/panzer199696-eng/uzel.git uzel
cd uzel
```

Репозиторий маленький (около 12 МБ): модель VAD (`core/uzel/models/silero_vad.onnx`)
лежит внутри, остальные модели качаются отдельно и в git не хранятся.

## 2. Окружение

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m pip install -e . --no-deps
```

Около минуты при тёплом кэше pip, до десяти — на пустом.

Последняя строка ставит сам УЗЕЛ в режиме разработки (P12, 24.09.2026): после
неё `uzel`, `uzel-bridge` и `uzel-mcp` лежат в `.venv\Scripts` и работают без
`PYTHONPATH`. Ставить только с `-e`: ядро ищет модель VAD рядом с
исходниками, обычная установка унесла бы код в `site-packages` без неё.

## 3. Настройки

```powershell
mkdir %USERPROFILE%\uzel-data
copy .env.example %USERPROFILE%\uzel-data\.env
notepad %USERPROFILE%\uzel-data\.env
```

> ⚠️ **`.env` — рядом с данными, не в корне проекта** (P11.2, 25.09.2026).
> В нём ключи, а `.gitignore` прячет файл только от git, не от облачного
> бэкапа. Другой путь задаётся переменной `UZEL_ENV_FILE`. Старый `.env` в
> корне проекта ещё читается для совместимости, но слабее нового и с
> предупреждением в журнале.

Умолчания: данные — в `%USERPROFILE%\uzel-data`, заметки — в хранилище Obsidian
`%USERPROFILE%\Documents\Obsidian`. Если у вас иначе — раскомментировать и поправить:

```ini
UZEL_DATA_DIR=D:\uzel-data
UZEL_VAULT_DIR=D:\Заметки
UZEL_USER_ROLE=инженер на стройке   # кто носит кулон — подсказка модели разбора
```

> ⚠️ `UZEL_DATA_DIR` держать **вне папки проекта и вне облачного бэкапа**.
> Туда пишется сырое аудио, база всех реплик и индекс поиска. Проект на
> Рабочем столе, заведённом в синхронизацию Google Drive, — готовая утечка.

> ⚠️ **Переменная окружения сильнее `.env`.** Если ядро упрямо ходит в чужой
> каталог, а в `.env` написано верно — проверь `echo %UZEL_DATA_DIR%`. Поймано
> 20.09.2026 на этой самой приёмке: унаследованная переменная тихо увела
> свежую установку в боевую базу.

> ⚠️ **Телефону нужен доступ снаружи?** Тогда `UZEL_HOST=0.0.0.0` — и
> **обязательно** `UZEL_API_TOKEN=секрет` в том же `.env`: без токена ядро
> с не петлевым адресом отказывается стартовать (P11), а с токеном всё,
> кроме `/health`, отвечает 401 без него. Токен передаётся параметром
> `?token=секрет` или заголовком `Authorization: Bearer секрет`.

## 4. Тесты

```powershell
.venv\Scripts\python.exe -m pytest -q
```

Ожидается: все тесты зелёные, несколько пропущенных. Сеть не нужна.
Пропускаются интеграционные (включаются `UZEL_RUN_INTEGRATION=1`) и живые
проверки смыслового поиска — пока модель эмбеддингов не скачана в
`UZEL_FASTEMBED_CACHE` (по умолчанию `%USERPROFILE%\models-fastembed`).

## 5. Первый запуск

```powershell
uzel.cmd serve
```

`uzel.cmd` — запускатор CLI: берёт python из `.venv` и работает из любого
каталога, не требуя активировать окружение. Равнозначно
`.venv\Scripts\uzel.exe serve` или `.venv\Scripts\python.exe -m uzel.cli serve` —
после шага 2 пакет установлен и `PYTHONPATH` не нужен.

Проверка в другом окне:

```powershell
curl http://127.0.0.1:8770/health
start http://127.0.0.1:8770/ui
```

`/health` отдаёт только живость и версию — он открыт без токена, его проверяют
мост и телефон. Версия, размер очереди и состояние приватности — в окне `/ui`;
`/ui` — страница со статусом, лентой дня, поиском и кнопками «Пауза 30 минут»
и «Приват». Статика своя, в интернет страница не ходит.

**На этом установка состоялась.** Дальше — то, что делает её полезной.

## 6. Расшифровка на видеокарте

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-cuda.txt
```

Два гигабайта колёс `nvidia-*`. `ctranslate2` не объявляет их зависимостью,
но при `device="cuda"` ищет `cublas64_12.dll` и `cudnn*.dll` **по PATH
процесса** — `os.add_dll_directory()` на это не влияет, проверено. Код сам
добавляет `site-packages/nvidia/*/bin` в PATH (`core/uzel/stt/local_backend.py:52`),
но добавлять нечего, если колёс нет. Без них всё работает — на процессоре.

Модель речи скачается сама при первом обращении (~3 ГБ). Чтобы положить её
заранее и не зависеть от сети, выгрузи в `UZEL_LOCAL_MODEL_DIR\large-v3` —
существование этой папки отменяет поход в интернет.

Замеры на GTX 1660 Ti (6 ГБ): `large-v3` с `int8_float16` занимает **1963 МиБ**.
`float16` вдвое медленнее и теряет текст, `int8` отличается на 3 %.

## 7. Разбор разговоров локально

Поставить [Ollama](https://ollama.com), затем:

```powershell
ollama pull qwen2.5:7b-instruct-q4_K_M
uzel.cmd llm-check
```

`llm-check` прямо говорит, чем разбираются разговоры и не уходит ли что-то
в облако. Ожидаемое:

```
модель разбора: ollama (локально), qwen2.5:7b-instruct-q4_K_M — готова
облако на штатном пути: запрещено (allow_cloud=False, облачных бэкендов в настройках нет)
```

Строка выводится из фактического состояния (P11.2): включишь в настройках Groq
или агент-шлюз (`gateway`) — она перечислит их; разрешат облако конвейеру — напишет «РАЗРЕШЕНО».

> ⚠️ **6 ГБ видеопамяти не держат whisper и модель разбора одновременно**:
> 1963 + 4140 = 6103 МиБ при 6144. Ночной батч поэтому работает в два такта —
> вся расшифровка, выгрузка whisper, весь разбор. Это не перестраховка,
> замерено 19.09.2026.

> ⚠️ Ollama держит модель в видеопамяти ещё `keep_alive` минут после ответа.
> Пока она там, whisper на карту не грузится и процесс молча стоит.

## 8. Конвейер

Два прохода, разнесены намеренно.

```powershell
uzel.cmd worker ingest --loop     # дешёвый: очередь -> VAD -> реплики, GPU не трогает
uzel.cmd worker batch             # ночной: расшифровка -> разговоры -> разбор -> выгрузка
uzel.cmd worker recover           # вернуть в очередь то, что оборвалось на полпути
```

Ночной батч останавливается по файлу `<UZEL_DATA_DIR>\worker.stop` и по пределу
времени (`UZEL_WORKER_TIME_LIMIT_S`, по умолчанию час) — и то и другое
проверяется между пачками, а не после всей работы.

## 9. Источники звука

**Кулон через ПК** (нужен Bluetooth LE):

```powershell
.venv\Scripts\uzel-bridge.exe --scan
.venv\Scripts\uzel-bridge.exe --address <MAC> --uid pendant-1
```

Пока кулон подключён к телефону, с ПК он **не виден вообще**: при активном
соединении BLE-реклама прекращается. Сначала отвязать от телефона.

**Приложение Omi без своего APK** — Developer Mode шлёт вебхуки в наше ядро,
адреса и оговорки в [06-совместимость-с-приложением-omi.md](06-совместимость-с-приложением-omi.md).

**Свой Android-клиент** — `bridge/android/`, сборка Gradle, см.
[bridge/android/README.md](../bridge/android/README.md).
Готовый APK — в Releases. Проверен на одном телефоне (OPPO Find N5, ColorOS):
звук с кулона, сопряжение, обновление прошивки по воздуху. Токен ядра вводится
в разделе «Настройки» (P11):
если ядро слушает не только localhost, без него всё, кроме `/health`,
отвечает 401.

## 10. Окно на ПК и автозапуск

```powershell
uzel.cmd app                      # ядро + окно + значок в трее
uzel.cmd autostart install        # ярлык в shell:startup, запуск через pythonw
uzel.cmd autostart status
```

## 11. MCP-сервер для Claude Code

```powershell
claude mcp add uzel --scope local -- <путь>\.venv\Scripts\python.exe -m uzel_mcp
claude mcp list
```

`PYTHONPATH` не нужен (пакет установлен на шаге 2); `UZEL_DATA_DIR` должна
быть видна процессу сервера, если каталог данных не по умолчанию. Семь инструментов, все
только на чтение: `search`, `conversation`, `day`, `facts`, `tasks`, `stats`,
`privacy`. Дословные реплики `conversation` отдаёт лишь по явному
`with_utterances=true`.

## Если не заработало

| Симптом | Причина | Что делать |
|---|---|---|
| `ModuleNotFoundError: No module named 'uzel'` | пакет не установлен в `.venv` | `.venv\Scripts\python.exe -m pip install -e . --no-deps` |
| Ядро пишет в чужой каталог данных | переменная окружения бьёт `.env` | `echo %UZEL_DATA_DIR%`, убрать её |
| Расшифровка идёт минутами | нет CUDA-колёс, считает процессор | шаг 6 |
| Батч молча стоит на загрузке whisper | Ollama ещё держит карту | подождать `keep_alive` либо выгрузить модель |
| `uzel.cmd` ругается непонятными символами | батник пересохранили в UTF-8 | вернуть ASCII: cmd.exe читает `.cmd` в OEM-кодировке |
| Кулон не находится сканом | он подключён к телефону | отвязать от телефона |
| Кириллица в выводе ломается | кодировка консоли | `PYTHONUTF8=1` (в `uzel.cmd` уже есть) |
| Первый запуск поиска «висит» | качается модель эмбеддингов, 255 МБ | не убивать процесс, дождаться |

## Что установка НЕ даёт сама

- **Замер WER** (критерий A1) — нужна запись своего голоса и её дословная
  расшифровка, см. `tests/wer/README.md`, потом `uzel.cmd wer <аудио> <эталон>`.
- **Кулон** — его нужно собрать и прошить: [09-сборка-кулона.md](09-сборка-кулона.md).
- **Откалиброванный фильтр качества** — `UZEL_QUALITY_ENFORCE=false` стоит
  намеренно: пороги в `config.py` пока гипотезы. Неделю пожить с
  `uzel.cmd quality-report`, потом включать.
