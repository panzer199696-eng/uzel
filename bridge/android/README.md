# УЗЕЛ — Android-клиент

*English → [README.en.md](README.en.md)*

Свой клиент для телефона: принимает звук с кулона по BLE и шлёт его ядру
УЗЕЛ по HTTP. Работает с кулоном на прошивке УЗЛА и с кулонами Omi. Это
замена приложению Omi без облака: в `:core` нет ничего, кроме Kotlin stdlib,
в `:app` используются системные API, Compose и библиотека Nordic DFU для
обновления прошивки кулона.

Текущая версия — **0.3.1**, история изменений в [CHANGELOG.md](CHANGELOG.md).

## Поставить готовый APK

1. Скачайте `uzel-android-<версия>.apk` из **Releases** репозитория.
2. Разрешите установку из этого источника и установите APK.
3. Выдайте разрешения: Bluetooth (поиск и подключение), уведомления и, на
   Android 17, доступ к локальной сети. Без последнего ядро в домашней сети
   недоступно.
4. В разделе «Настройки» укажите адрес ядра (`http://<IP-ПК>:8770`) и токен, если
   ядро слушает не только localhost (см. [docs/07-установка.md](../../docs/07-установка.md),
   раздел «Настройки»).
5. Включите мост. Первое сопряжение с кулоном на прошивке УЗЛА проходит,
   только пока кулон подключён к USB (или ещё ни с кем не сопряжён).

⚠️ **Сборка в Releases подписана отладочным ключом** (debug). Это не ключ
магазина приложений, и он ничего не говорит о происхождении файла. Ставьте APK
только из Releases этого репозитория. Если нужна своя цепочка доверия, соберите
APK сами. Отладочный APK не обновится поверх APK, подписанного другим ключом:
сначала удалите старый (адрес, токен и неотправленный звук при этом сотрутся).

## Собрать самому

Нужны JDK 21 и Android SDK (compileSdk/targetSdk 37). AGP 9.4.1 и Gradle 9.8.2
приходят через wrapper в проекте.

1. Создайте в `bridge/android/` файл `local.properties` с путём к SDK:
   `sdk.dir=D\:\\Android\\Sdk` (Windows) или `sdk.dir=/home/<имя>/Android/Sdk`.
2. Соберите и прогоните тесты:

```
cd bridge/android
gradlew.bat :core:test :app:assembleDebug        # Windows (JAVA_HOME → JDK 21)
./gradlew :core:test :app:assembleDebug          # Linux / macOS
```

APK появится в `app/build/outputs/apk/debug/app-debug.apk`. Если на Windows путь
к проекту содержит не-ASCII символы, каталоги сборки сами уезжают во временную
папку (`<TEMP>\uzel-android-build\{core,app}`), иначе ломается classpath
тестов. Gradle печатает итоговый путь к APK.

3. Установите на телефон с включённой отладкой по USB:
   `adb install -r <путь к app-debug.apk>`.

## Что здесь есть

| Модуль | Что внутри |
|---|---|
| `:core` | Чистый Kotlin/JVM, ни одного импорта `android.*`: разбор пакетов, счётчик потерь, буфер кадров, дисковый спул, HTTP-клиент, аплоадер |
| `:app` | BLE-клиент, служба переднего плана, экран на Compose, плитки быстрых настроек, обновление прошивки кулона, автозапуск после перезагрузки |

Вся логика, которую можно проверить без телефона, живёт в `:core` и
покрыта unit-тестами. В `:app` — только то, что без телефона не работает.

## Что проверено, а что нет

**Проверено:**
- `:core:test`: unit-тесты на чистой JVM (протокол, буфер, спул, отправка
  на настоящий HTTP-сервер из JDK);
- на живом кулоне и телефоне OPPO Find N5 (ColorOS): приём звука по BLE без
  потерь (05.10.2026), сопряжение с прошивкой УЗЛА, обновление прошивки кулона
  по воздуху (0.1.2, 26.10.2026), живучесть службы на ColorOS (23.10.2026).

**Не проверено:** другие производители и их «убийцы» фоновых служб, другие версии Android
(minSdk 26), автономность телефона за сутки носки.

## Экран и живучесть на ColorOS

Разделы: **Кулон** (живое состояние, заряд, потери, приватность ядра), **День**
(разговоры, задачи, факты из `/ui/api/day`), **Заметки** (свои заметки и *метки
момента* — заметка со временем, к которой подтягивается разговор, записанный в
ту минуту), **Поиск** по памяти ядра. Плитки в быстрых настройках: «УЗЕЛ»
(вкл/выкл моста) и «Метка»; ярлык «Метка момента» на иконке.

**Почему мост «умирал при закрытии».** ColorOS (Athena, `SwipeUpClearAction`)
при смахивании карточки из «Недавних» бьёт весь пакет сигналом 9, стирает его
будильники и запрещает системе перезапуск службы
(`OplusAppStartupManager: prevent restart service`). Не помогают ни
START_STICKY, ни белый список батареи, ни «Разрешить работу в фоновом
режиме». Решение: окно не оставляет
карточки в «Недавних» (`excludeFromRecents` + `finishAndRemoveTask()` в
`onStop`), смахнуть нечего; служба живёт — проверено смахиванием и «Закрыть».
Сторож (`Watchdog`, будильник раз в 5 мин) поднимает службу после прочих
убийств, `BootReceiver` — после перезагрузки и обновления.

**Уведомление** у службы обязательное, но канал минимальной важности: в
шторке и строке состояния ColorOS его не показывает.

**Android 17 (targetSdk 37)** требует `ACCESS_LOCAL_NETWORK`, иначе запросы к
ядру в домашней сети молча падают и звук копится в спуле. Разрешение из той
же группы, что Bluetooth, — выдаётся вместе с ним.

## Почему Opus, а не PCM

Кулон кодирует звук сам; Bluetooth-канал узкий, а Opus 16 кГц при
24 кбит/с занимает 2,8 КБ/с против 32 КБ/с у сырого PCM — в одиннадцать
раз меньше. Телефон принимает уже готовые кадры Opus и пересылает их ядру
как есть (тело запроса — кадры с префиксом длины, формат `opus-frames/1`);
декодирует воркер ядра, а не телефон. Экономится и батарея, и трафик.

## Если ядро отвечает 204

Это **не ошибка**. Так ядро говорит «запись заглушена приватностью»:
данные не нужны, фрагмент выбрасывается и в буфер не ложится. Когда
заглушку снимут, новые фрагменты снова начнут приниматься. Ошибкой стоит
считать только недоступность ядра — тогда фрагменты копятся на диске
(лимит 256 МБ, дальше удаляются самые старые) и досылаются по
восстановлении связи, в исходном порядке.
