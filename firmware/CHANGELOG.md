# Прошивка УЗЛА — история версий

## 0.1.3 — 27.10.2026

**Звук:** цифровое усиление после ФВЧ +24 → +18 дБ (`DSP_GAIN_DB`).
Замер после носки (записи с телефона, 26–27.10, 7,7 ч): с 0.1.x речь −43 → −28 dBFS,
гул ниже 30 Гц 52 % → 0,1 %, но в 14–15 % фрагментов звук доходил до полной шкалы
через лимитер (на старой прошивке — 1 %). Модель на 800 фрагментах 27.10 (обратный
лимитер → −6 дБ → лимитер): таких фрагментов ~0 %, речь −35 dBFS — на 8 дБ громче 0.0.x.

## 0.1.2 — 26.10.2026

Код тот же: версия для проверки обновления по воздуху с телефона (Android-мост 0.3.1).
0.1.1 залита по воздуху с ПК 26.10 (257 712 байт, CRC сошлась, сопряжения сохранились).

## 0.1.1 — 26.10.2026

Код тот же, что у 0.1.0: версия для первой проверки обновления по воздуху с ПК
(`python -m uzel_bridge --dfu`). Загрузчик на кулоне с этого дня — Adafruit 0.11.0.

## 0.1.0 — 26.10.2026

Первая своя версия. База — сборка `omi_2.0.10_triangle` (исходники Omi DK2 2.0.10),
коммит 69d3642 воспроизводит её побайтово.

**Звук**
- ФВЧ 120 Гц (Баттерворт 2-го порядка) до кодека. Замер на 1,6 ч записей: 71,5 % энергии
  было ниже 30 Гц (удары, шаги, одежда), клиппинг в 21 % фрагментов.
- Аппаратное усиление PDM +12 → 0 дБ, после фильтра цифровые +24 дБ и мягкий лимитер
  (−1 dBFS). Итого речь на +12 дБ громче прежнего без клиппинга от ударов.
- Кадр Opus 10 → 20 мс (тот же битрейт 32 кбит/с, меньше накладных расходов).
- Кадр ограничивается под MTU соединения ещё в кодере: мосты не собирают кадр из кусков.

**Ошибки**
- Размер пакета брался из длины пакета канального уровня (251), а не из ATT MTU: при
  MTU 23 звук не уходил совсем. Теперь кулон сам начинает обмен MTU и режет кадр под него.
- Поток отправки крутился без пауз при пустой очереди — процессор не засыпал.
- Три повтора по 1 мс на занятый буфер BLE → кадры терялись при любой задержке. Теперь
  ожидание до 200 мс, очередь 2 с вместо 0,32 с, кадр уходит после переподключения.
- Обработчик подключения не проверял код ошибки и делал `unref` без `ref`.
- `ASSERT_TRUE(a == b)` раскрывался в `(!a) == b` — проверки не работали.
- `RESETREAS = 1` сбрасывал один бит из всех.
- Сбой запуска оставлял кулон «живым» без звука/BLE: теперь код ошибки вспышками и
  перезагрузка через 10 с.
- Двойная инициализация батареи (main + transport).
- Кварц HFXO для микрофона включался записью в регистр в обход MPSL — когда радио
  молчало, MPSL его гасил, и PDM работал от RC-генератора (±1,5 % к частоте
  дискретизации). Теперь запрос через диспетчер часов.
- Прерывание PDM через `nrfx_isr` вместо голого `IRQ_DIRECT_CONNECT` (без выхода через
  планировщик поток кодека просыпался с задержкой).
- Сбой ядра (стек, `BT_ASSERT`, таймаут HCI) — перезагрузка вместо тихой остановки
  (`CONFIG_RESET_ON_FATAL_ERROR`).
- Хранилище ключей поднимается до `bt_enable`; не поднялось — раздел стирается, а не
  цикл перезагрузок без рекламы.
- Места под ключи (3) кончились — на USB освобождается одно под новое устройство.

Ревью кода прошивки 26.10.2026 (независимая проверка по исходникам NCS 2.7.0) — все
находки «важно» закрыты: обрыв больше не стирает очередь звука (MTU 0 после разрыва
принимался за «кадр не влезает»), см. пункты выше.

**Безопасность**
- Подписка на звук, вход в DFU и статистика — только по шифрованной связи. Сопряжение
  Just Works, новое устройство принимается, только пока кулон ни с кем не сопряжён или
  подключён к USB. Ключи хранятся во флеше (до 3 устройств).
- Раньше любой телефон рядом мог слушать звук и одной записью уронить кулон в загрузчик
  без таймаута.
- Соединение без шифрования рвётся через 30 с — чужак не держит единственный слот.

**Прочее**
- Имя в эфире `UZEL`, DIS: `UZEL` / `UZEL Triangle v1`, версия `0.1.0`.
- Сервис статистики `5a0e1000-…` (счётчики кадров, потерь, время кодирования, MTU).
- Светодиоды: вспышка раз в 3 с вместо постоянного свечения; зелёный — на зарядке.
- Удалены модули SD-карты, динамика, кнопки, вибро, NFC, акселерометра.
- Уровень батареи — прежняя шкала (множитель делителя ×3 записан явно).
